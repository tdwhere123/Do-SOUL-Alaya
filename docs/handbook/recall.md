# Recall

This is the live Recall mechanics owner (invariant §32). See
[invariants](invariants.md) for must-not-break rules and
[architecture](architecture.md) for package, write and effect ownership.
Alaya is a memory plane for CLI agents: an information index is a delivery,
not proof that the agent used it or that a source statement is true.

## Fallible interpretation and task use

Authorized source records, the original task, Q (query interpretation), H
(source interpretation) and C (their explicit semantic correspondence) have
separate identities and authority. Structural admission, exact source binding
and a successful conditional computation do not certify model fidelity, source
coverage or world truth. A declared gap need not enumerate silent omissions.
An unresolved premise restricts its dependent conclusion, not independent
source access. Repeated derivations are not independent confirmation. Explicit
hypotheses and source-bound selected interpretations remain unreviewed and keep
all premise, source and dependency qualifiers; they never promote a
`RelationAssertion` or use an ordinary world-claim projection. Further task
observation and revision belong to the caller, not an autonomous Recall loop.
There is no natural-data gain, complete task frontier or robust final-answer
claim from mechanism tests or delivered source hits alone (invariants §12c–d).

## Current route and ownership

```text
retained sources / governed assertions / EventLog
  -> Storage source and relation projections, SourceIndex
  -> pinned native readers and interpretation clock
  -> RecallService.recall / executeRecall
  -> compileConditionalFieldQuery -> observeField -> projectAcceptingIndex
  -> fitted InformationIndex + same-order results
  -> MCP soul.recall / CLI fallback
```

The ordinary route is `native_query`; Core rejects explicit historical
`canonical` and `associative` enumeration rather than silently selecting an
old algorithm. Retained schemas and offline archive readers do not execute the
retired comparison, prefix, flood, SliceKey, Gamma, fusion or budget-aware-q
selectors. `RECALL_CONSUMER_PROTOCOL_VERSION` negotiates source-evidence
support, not ranking. Mixed and source-only requests require declared
source-evidence capability; the explicit compatibility view is
`result_kind_view: "memory_only"`.
Incompatible consumers receive an error rather than a silently reduced index.
The worker RPC uses a versioned result envelope, not a bare index.

[Protocol conditional-field contracts](../../packages/protocol/src/recall/conditional-field/)
own tagged targets, query, index and continuation schemas;
[Core Recall runtime](../../packages/core/src/recall/runtime/) owns compilation,
observation, conditional proof, projection, page fit and request accounting;
[Storage root readers](../../packages/storage/src/repos/field/) and
[SourceIndex](../../packages/storage/src/repos/source-index/) own bounded
native reads and derived index state. The daemon wires snapshot leases,
worker affinity and MCP/CLI encoding. `PathRelation` is a rebuildable
current/as-of projection of immutable governed relation history, not another
ontology or a license to infer proof from graph connectivity (invariant §12).
Recall performs no provider call, embedding generation or index backfill.
The read worker imports source locator binding and semantic unit indexing from
`@do-soul/alaya-soul/source-read`. This entry re-exports their existing Soul
owners without loading the Garden and tool barrel; both remain eager imports.

## Conditional meaning

A field product retains its tagged memory or native source-evidence target,
hypothesis, program state, binding and temporal coordinates. Source-record-only
results use their own root/revision/digest identity; no memory or capsule ID is
minted. The compiler admits typed query meaning and located interpretation
holes; unsupported producer, guard or program cannot silently become a
successful empty query. A proposed guard has no caller-owned verdict: Core
rechecks source, equality, authorization, binding and time against captured
current authority. Requested source observation time, semantic `as_of`,
storage time and lease lifetime remain separate. Unknown source time is never
inferred from `created_at`.

Association is `assoc.bottleneck.milligrade.v1`: compatible serial/AND paths
use minimum, OR alternatives maximum. Separate rule instances, witnesses and
alternative roots remain separate even at equal grades. Hard admitted relations
transfer at identity (1000); a relation name alone carries no grade. An
associative view requires a declared common cap contract: incomparable domains
are not assigned a fabricated scalar. A reachable grade zero differs from no
activation. Causal support requires admitted current evidence; a lexical hit,
vector hit, source mention, search hint or common-cause unknown is not a causal
claim. Optional stored cosine admission needs an explicit prepared producer,
current source provenance, matching query/object vector profile and threshold;
reader presence alone creates neither obligation nor seed. See
[query compilation](../../packages/core/src/recall/conditional-field/query/)
and [field engine](../../packages/core/src/recall/conditional-field/engine/)
for supported grammar and exact equations; this handbook does not replace them.

## Bounded observation and delivery

SourceIndex is the native ordinary discovery owner. It includes current
`SourceRecord` bodies **and** standalone retained `evidence_capsule` text
(`excerpt ?? gist`); a capsule has its own root kind, revision and digest, and
`source_id: null`. It is not a SourceRecord mirror or a gist-first bypass of
SourceRecord. Interpretation provenance capsules carry a storage-only create-time
`source_provenance` role and are excluded from standalone native membership. An
independent capsule citing the same source hash remains eligible: hash equality is
not role identity. SQLite migration 027 adds the role with default zero; it does not
infer or backfill historical roles from text or hashes. Core's provenance creation
owner persists it in the same transaction as the capsule and EventLog entry.
Scoped records require governed authorization; a capsule with no
scope is eligible only to the unrestricted principal. Lexical and inspected
vector windows nominate candidates; their ordinal navigation witnesses are
not association grades, assertion support or proof. Optional inference is
prepared before the read snapshot against an already eligible active generation.
A missing/unbound model or index does not silently become an empty corpus.
Bounded capture, read refusals and rejected candidates consume allowances;
query-time Recall never repairs the index. Unbinding retires eligibility and
fences old selections. See
[SourceIndex lifecycle](../../packages/core/src/source-index/source-index-lifecycle.ts)
and [native root reader](../../packages/storage/src/repos/field/bounded-source-root-reader.ts).

One ordinary request pins its snapshot, mutation generation and interpretation
clock; native readers have bounded scans and byte reads, not free enumeration of
an entire library. Native nomination runs once under its own acquisition ledger:
the allowance bounds lexical attempts, retained roots and inspected vector windows;
the active snapshot's metadata sizes and dimensions fund the native read/decode
reservations, currentness guards and exact scoring. It does not spend the first
delivery page's exploration work. The `acquire` receipt phase records actual work,
native bytes and elapsed time, while retained nominations consume field memory.
An over-cap window-id prefix stays partial and is not an exact whole-generation
ranking. Exact vector scan still visits every admitted window in that prefix; each native page sizes
metadata once per previously unowned root and validates each candidate while computing cosine in one pass.
The existing conservative logical work charge is retained, so the optimization does not buy extra
windows or silently change a budget-limited result. Missing/unbound generations remain unavailable, independently of lexical
discovery. Protocol 24.0.0 versions this ordinary membership/ranking change under
invariant §25; existing queries must restart after upgrading.
The complete source census and current-source ordering are
separate from a selected prefix: currentness uses the greatest exact UTC
recorded instant then record identity before scope/retention checks, and cannot
resurrect an older revision. A scanned, unavailable, stale or unvisited root is
not proof of absence. A source-root read verifies workspace, scope, version,
digest, lifecycle and UTF-8 extent. Unavailable/corrupt retained chunks fail
closed, with no query-time backfill. Physical chunk reads and metadata are
charged even when only a short excerpt is returned. The public source identity
and any verified capsule alias are preserved across proof and delivery.

Core retains numeric preparation, relation and fact demand cursors, possible
and guaranteed bounds, proof traversal and projection across bounded pages.
One relaxation advances at most one edge; stopped work retains its cursor.
An unfinished possible solve is **not** a certified upper bound. Even a
certified upper bound cannot exclude a lower-valued comparison match: that
requires a lower-bound premise. Newly admitted identities and facts reopen
affected demands; an exhausted native page proves only its demanded keys
for this query and snapshot, not a closed language universe. Guard replacement
waits for complete reevaluation. Retained grounding dependencies and revisions
remain attached to their proof; missing nodes, cycles, withdrawn support or
incomplete work cannot become an empty successful explanation. Named comparison
operands retain all admitted referent alignments, with metered pair preparation;
the first convenient alignment is not a complete comparison. Proof dependencies
and alternative roots survive identical scores. See [observation](../../packages/core/src/recall/runtime/conditional-field-observe.ts)
and [accepting projection](../../packages/core/src/recall/conditional-field/index/project-accepting-index.ts).

Supplied proof forests and support may use an owner-issued immutable
`explanation_source_revision` across continuations. It covers the entire forest and
support, stays stable for equivalent copies, and changes whenever either changes.
Core retains the original captured inputs for that revision. Without a revision,
changed forest or support references conservatively restart proof preparation, so
callers reconstructing those arrays on every page cannot rely on eventual progress.
Missing or cyclic derivations invalidate the projection; a proof exceeding the
protocol's output-array capacity receives a resource rejection. Emitting a complete
proof also requires enough current-request finalization work to assemble its nodes,
roots and selected-page views. Preparation that advances retained cursors can defer
this copy to a later page. If an attempt cannot fund the copy and makes no retained
preparation progress, membership and available claims remain usable and the payload
reports `resource_rejected`; the discarded proof cursor does not advertise endless
progress. Membership continuation ends on
that refusal; source entries can retain a capability solely for explicit body
expansion. That capability cannot restart membership or proof traversal, and reading
the body preserves the proof's payload rejection. If other membership was still
pending, transport is also resource-rejected.
A pending logical index is likewise resource-rejected rather than complete.
A new request with sufficient finalization allowance can obtain the complete proof.
Proof cursors that survive delivery must also fit alongside its mandatory retention
ledger. A cursor that cannot coexist with that ledger is discarded with an explicit
payload resource rejection; fitted membership remains usable. Completed cursors that
are released before commit do not share that retention lifetime.

The index distinguishes interpretation, observation, logical-index, transport
and payload completeness. `exhausted` describes a reader, not necessarily
query-relative closure or absence of a counterfactual influencer. A partial
page, proof, payload or output cap cannot be reported as complete-empty.
Membership, explanation and preview work share request accounting. A selected
conclusion is not delivered if its required assumptions/support do not fit;
omission keeps its status. The public `index` is authoritative; required
`results` encode its delivered entries in the same order with binding and
product coordinates. A source root occupies one slot even with multiple
independently identified Q/H/C proof qualifiers. A source-only slot remains
source evidence, not semantic proof. Fit, deliver, acknowledge and final
settlement have distinct owners: a fit is not a persisted delivery or usage.

A continuation is bound to request, scope, interpretation, snapshot/generation,
process-local reader and issued page. It cannot rescan or reselect a frozen
population; a mutation, expired lease or lost worker invalidates it. Prepared
pages advance only after delivery acknowledgment checks the current snapshot.
An acknowledged page and delivery identity can be replayed without double
debit; uncertain acknowledgment cannot be invented as rollback. Payload
continuation is bound to an already delivered source in that query epoch and
retains its offset and cap. Permission is explicit: an unrestricted local
principal is `authorized_scopes: null` (key present), `[]` admits none, and a
missing ordinary worker authorization key fails closed. Do not substitute a
workspace default. Source-semantic attached-agent handles have their own
explicit principal and lifetime admission, not a reusable ordinary worker key.

Protocol 35.0.0 separates deterministic semantic query identity from a random,
server-owned execution identity. Each independent start owns its field state;
opaque continuation capabilities select that execution, and preparation CAS and
retry delivery IDs apply only within it. Equal queries, snapshots and clocks do
not alias mutable sessions. Field and issued-page admission commit together;
a failed capacity check or competing acknowledgment cannot overwrite a winner.

The process-local [execution retention owner](../../packages/core/src/recall/runtime/recall-execution-retention.ts)
accounts fields, worker preparations and issued pages together, with conservative
object-graph bytes (including full typed-array backing buffers). Independent
retained roots pay separately for shared nodes. The default ceiling is 128 MiB
per process/Worker and 64 MiB per workspace within it; capacity exhaustion is an
explicit `execution_retention` resource refusal and never evicts a valid lease.
These are retention estimates, not heap/RSS guarantees or request-work charges.
Executions expire at the earlier of their admitted lifetime and five minutes;
an active timer drops references even when no token is used again. Acknowledgment
releases preparation/source-reader closures; its conservative reservation and
retry receipt remain until expiry. Terminal replay may retain the field needed
for source eligibility checks during that lease. Expiry, discard and invalidation
notify the parent to revoke the affected Worker affinity handles; Worker exit
revokes all its routes. Source-currentness and authorization checks remain separate
from TTL. Older process-local handles cannot resume after upgrade or Worker restart.

## Minimal statement navigation

Protocol 31.0.0 (`ordinary-native-field.v8`, invariant §25 major) admits
`source-statements-v1` artifacts as auxiliary keys of an existing source message.
The ordered session producer emits only `{text, relation}`; the host supplies message
identity, role, recorded time and byte extent. Core verifies the captured source root,
currentness, scope and occurrence inventory at publication and inside writes. It
persists provenance evidence before optional generic observation memory; retry never
deletes evidence to compensate for a later memory failure. Explicit agent-authored
signals and `soul.interpretation` H/Q/C remain separate supported APIs.

The same admitted artifact supplies lexical and selected-space vector key text.
Artifact/key digests are not raw-body digests or independent source roots. SQLite
invalidates generation eligibility when the key set changes, and readers check raw
source currentness plus artifact availability. Archive/erase withdraws keys. Missing,
failed or empty statement extraction leaves raw source keys available. Statement
hits retain their raw host message coordinates and existing raw display semantics;
no assistant relocation or new display selector is implied. Historical extraction
records retain their own interpretation and erase dependencies, not new admission
under the minimal contract.

Protocol 33.0.0 produces these artifacts from `SOURCE_STATEMENT_SESSION` work: one
session per host-session container (`host-session:<container key>`), over its round
roots in round order, attributed to the run that captured the round. A chunk is planned
only once closed (a later message starts the next chunk, or the container is idle for
the 15-minute host-worker fallback interval), so a queued request never changes.
Message time shown to the model is the host-reported time when the host gave one; the
statement observation is the round root's receipt. Recent context is the longest suffix of preceding messages within 16 KB and
64 messages. Each statement binds to its own message root; the other roots its request
showed the model are its context dependencies and withdraw it on erasure.

## Question-time preference

Protocol 28.0.0 admits `interpretation_proposal.question_time` from the narrow
`alaya.query.question-time.v1` producer. The proposal binds the original-query digest
and interpretation clock, and contains up to 32 closed UTC calendar-day intervals on
source `event_time`. Formation reads only the question and clock; Recall performs
no provider call or language-specific time inference. The retired ordinary English
failed-deployment demo no longer creates a program, hypotheses or claim demands;
semantic programs must be explicit inputs from declared producers.

The time coordinate is a soft preference, not a source guard. Native acquisition
orders in-window roots from the original bounded prefix first, then time-restricted
lexical candidates with the original query and existing lexical statistics, then the
remaining original prefix. One shared 128-attempt and 16-retained-root allowance still
applies; a preferred candidate can displace a fallback root, never make it ineligible.
There is no per-question FTS corpus or unbounded union. Under Protocol 29, restricted
and unrestricted queries use the same selected generation's FTS statistics; an unbound
or cold raw fallback explicitly retains database-wide statistics. Unknown source time
is not inferred from ingestion time. Under Protocol 34 the preferred domain is a root whose
recorded date lies from the window start to the interpretation clock (a past event is
recorded at or after it happens). Empty windows and windows wholly after the clock yield
no preference and preserve nomination order. Unavailable time reads remain explicit partial outcomes, not successful absence.
Public `since`/`until` retain their hard-filter semantics independently of preference.

Native navigation consumes the bounded source permutation separately from capture
ranks. Restricted lexical occurrences and rank summaries carry `domain: "question_time"`; their ranks
remain local to that capture and are validated independently of unrestricted ranks.
This capture is not an additional round-robin opportunity or allowance. Preference
permutes source positions in the mixed access schedule, preserving memory positions
and native order within each source tier. Continuations retain that frozen order;
public navigation exposes factual capture provenance and the separate access ordinal.

Protocol 36.0.0 adds optional `source_template` to the ordinary interpretation proposal.
Producer `alaya.query.source-template.v1` may supply it and question time, bound to the
original query digest and interpretation clock. Its known asked host role and exactly
one evidence statement with one nonempty `<...>` hole define a narrow navigation frame.
Protocol's FTS surface-token owner preserves ordered Unicode letter/number/underscore
tokens and their offsets, including case and duplicates; it does not normalize, segment,
stem or truncate. Both literal sides must occur contiguously and in order with at least
one intervening token in a current statement and its own bound retained host message.
The occurrence must be complete; exact retained bytes do not claim upstream original-byte
fidelity. Session-context messages cannot supply either side. UTF-16 token positions are explicitly
converted to UTF-8 source positions.

After active soft time preference completes, acquisition inspects every eligible root
from the original admitted prefix (at most 16). Known empty current artifacts are
nonmatches; partial, stale, unread or refused evidence leaves uniqueness unknown.
Exactly one matching root may be restored only when time preference displaced it;
it precedes the incumbent nominations under the unchanged 16-root cap. Authorization,
source restrictions and hard time filters remain authoritative. An explicit hard source
guard disables template inspection: acquisition lacks the later Field facts needed to
prove eligibility, so it preserves the incumbent. The complete incumbent
capture is retained before optional inspection, while a conservative association bound
protects finalization and graph retention. Optional reads and replacement capture use
only the remaining allowance and remain charged on refusal; the paid incumbent survives.
Association is finalized once after membership is settled. The observation records its
source/artifact identities, current bindings, index binding, admitted-prefix authorization
and matching source coordinates. These are navigation witnesses, not entailment or
event-time proof; quoted or negated text can still match a literal frame. Proposal absence
preserves the existing path and Recall makes no new provider or embedding calls.

Protocol 39.0.0 deepens the opt-in `alaya.query.source-task-observation.v1`
phase. The [observation authority](../../packages/protocol/src/recall/conditional-field/source-task-observation.ts)
carries explicit Q branch, H frame and optional temporal-slot endpoints plus the
selected correspondence identity. The [formation input](../../packages/protocol/src/recall/conditional-field/source-task-observation-formation.ts)
supplies Q, C and the exact selected published H. Descriptions and the retained
legacy `task_correspondence.component` are not executable semantics. Missing Q/H/C
or endpoints mean unavailable for this association computation, not source absence.

After retaining the paid incumbent, Core binds the original query and clock and
compares the observation excerpt and source clock with Storage's current raw read.
Storage rechecks each nomination's currentness, dependencies and erasure. Auxiliary
statement nominations first pass their own complete admission, then read their current
raw source; their statement `body_bytes` and `source_span` are not raw excerpt bounds.
The Worker loads the selected H through the existing publication/source verification
owner in the same snapshot. No supplied interpretation ID bypasses lifecycle, scope,
source version, digest or literal location verification.

[Conditional binding](../../packages/core/src/source-index/task-observation-binding.ts)
uses the existing Q/H/C admission and `executeSourceSemanticInterpretation` →
`observeField` computation. Only a supported binding of the supplied Q branch/frame
to the supplied H frame can enter the existing task preference. Existing branch-local
evidence support remains distinct from complete-query support and task-operation execution.
An unresolved branch is not a temporal mismatch. No possibly-equivalent C relation,
component-string comparison, timestamp-derived event identity or confidence score is used.

An interpreted interval must explicitly name a slot on that same H frame. Its bound
referent must support the exact temporal expression at the observation's raw-source
UTF-8 coordinates. This qualifies a fallible calendar-interval observation of that
operand; it does not equate a date window with an entity or prove fidelity, occurrence,
applicability or world truth. Comparison with the independently proposed question
intervals remains `hypothesized_overlap`, `hypothesized_disjoint` or `unavailable`.
A standing statement may supply a supported evidence-input branch without an
occurrence-time or current-truth gate. A binding with unavailable time establishes no temporal match; its conditional Q/H/C
claim remains only a source-local report.

The independently active question-time phase, bounded original/incumbent union,
16-root cap and existing overlap/other-task-evidence/incumbent order remain the owners.
No support-first library queue or input-coverage selector is added. Hard guards,
explicit source filters, prepared hints and non-epsilon programs still abstain before
optional acquisition. Source-template and task-observation proposals do not compose
into a second schedule. Validation, verified H reads and conditional computation share
the remaining optional allowance; resource refusal preserves the paid incumbent.
There is no provider call, index repair, extra quota or default promotion.

Protocol 39.1.0 corrects qualification identity and support closure. Navigation retains
the actual conditional-computation and canonical bounded binding identities, including
multi-phase prefixes, without renaming them. The required support
extent comes from the selected binding's full executed proof closure through the existing
dependency/location owners, not the union of independent proofs. An unlocated independent

prevents qualification. The shared payload fit uses that explicit extent, not the discovery window, while keeping its normal byte
limits and continuation accounting. A navigation observation is not itself a claim that
its entire support was delivered: the result's actual span/preview remains authoritative.
Source record, interpretation and field continuation invalidation remain independent.

The private native observer captures the original and incumbent prefixes before optional
inspection. It remains bounded diagnostic evidence, not a public eligibility census,
source relevance proof or new route. Missing/partial acquisition is not complete-empty.

The [formation owner](../../apps/bench-runner/src/runs/source-task-observation/formation.ts)
exposes request-bound endpoint references in its existing observation request. Its

Ready coverage means one admitted row per supplied source with no row diagnostics,
not coverage of all Recall candidates, endpoint availability or relevance. The producer's

The canonical public observation and native v13 contract are unchanged (invariant §25);
manual MCP proposals still use their existing canonical association and native verifier.
Legacy unbound observations remain parseable for source-local diagnostics and Protocol 38

## Evidence statement coverage

Protocol 40.0.0 replaces the retired slot-5 two-coordinate swap. An ordinary request may
carry `interpretation_proposal.evidence_statements`: one to four question-formed,
instance-shaped sentences (at most 512 characters each) admitted by the question-time and
source-template producers and bound into query identity. Before the snapshot, each statement
is embedded with the query's own binding, one input at a time and only through local
inference; the worker uses a vector only when its input digest and profile match the
admitted text and the query.

Acquisition retains at most 16 statement-key vectors per root seen by the original query's
vector scan, as before. Only allowance-funded ordinary acquisition associates; request-funded
Source library pages do not. When statements are bound, acquisition charges exact scoring on
its own ledger and keeps only coverage: for each root and statement, the best cosine over that
root's retained keys (null without a key). Keys never leave acquisition. Without statements,
the keys are dropped and the field order is unchanged.

Navigation applies the coverage after filtering and time preference determine the source
order. A statement's top root is the highest-coverage root in that order, ties to the earlier
position. Starting from the source first five with slot 1 fixed, each statement in order whose
top lies outside the first five replaces the last root at slots 5..2 that tops no statement;
nothing changes if every slot 2–5 serves. All other roots keep their source order, so replaced
roots follow directly after the first five. No root leaves the order and memory keeps its
positions. The navigation diagnostic `evidence_coverage` reports the statement count, each
top's source position, every injection or `no_free_slot`, and refusal.

Optional retention or ordering exhaustion preserves base nominations/order before any
permutation is applied, records refusal, and cannot silently retry on a later page. After a
permutation has been applied, a later underfunded request fails explicitly instead of
reverting to baseline order. Child refusal requirements include the mandatory navigation
reserve when translated back to the request budget. Coverage is a selection heuristic, not
proof that the injected root answers the statement: a top can be a near duplicate or a wrong
fact. Frozen, label-selected screens show gains and losses and do not establish natural-data
acceptance.

## Versioned cutoff measurement

Current bench-runner visibility uses `consumer-message-visibility-v2`: admitted whole-message
witnesses establish Any at every containing frozen cutoff even if later positions were not
collected. Absence still needs a complete cutoff or authoritative exhausted tail; All additionally
needs complete, nonempty gold mapping and every member visible. Invalid page/body admission
cannot prove a positive. Collection completeness, observed positions and exhaustion are separate
from proposition status. Source-root metrics share this collection gate but retain their distinct
source/proof admission; a source hit is not a body witness.

The historical v1 scorer remains available for replay. Acquisition reports v2 plus same-input
historical differences; conditional-navigation evaluation v3 identifies v2 visibility in each
summary and retains historical rows. Such differences are measurement-contract changes, not
algorithm gains. Unknown samples remain in denominators and support sufficiency stays unmeasured.

## Ordinary native field delivery

Current public `QueryView` defaults to `native_query`; field index and
continuation use `ORDINARY_NATIVE_FIELD_RESULT_VERSION` (`ordinary-native-field.v14`, Protocol
40.0.0; library field protocol 14). Ordinary delivery is a semantic major under
invariant §25: old continuations cannot execute the new policy (see the
[cutover and rollback entry](../../CHANGELOG.md)). A native vector hit locates a
root; observation and initial payload reading start at byte zero in document order.
The navigation witness retains the actual matched window, but does not cap or
anchor ordinary payload bytes. Explicit semantic proof-support ranges and payload
continuation offsets remain authoritative for their respective reads. Source
previews keep the same root order and declared budgets. Within the fitted allowance,
they end at the largest recorded boundary of the coarsest available unit: an admitted
`message` span where recorded, otherwise a `line` span. When a later member would
expose only a fragment but a complete unit fits a fresh page, the codec refuses that
wider membership fit. The projection owner pays for the attempt, refits a shorter
prefix and leaves the deferred member pending. This may increase page count and
framing work; it is not free payload expansion or a ranking change. A first unit
that cannot fit even a fresh page still uses a nonempty UTF-8 prefix, as do sources
with unavailable or empty boundaries. No source is deferred indefinitely. Role markers and inferred messages
are not boundaries. Verified retained-source reads precede the bounded structural
lookup; native lookup work and metadata share the payload request ledger.
Unavailable, unreadable and bounded-out lookup states remain distinct from a
successful empty span set. Framing retains the actual delivered end and
completeness; payload continuation starts at that end. Replay reuses the fitted
page and its recorded facts, not a new selection or uncharged source scan.

Hosts read cut sources before answering: each source result of the first pages whose
span is not `content_complete` is continued with `payload_continuation` from its
`content_end` until complete (attach and server instructions, `soul.recall` description).
The cut is a page-fitting boundary, not a relevance judgement; measured on LongMemEval,
reading the first pages and then continuing their cut sources (≈ 9 KB more for the first
five) is what reaches the recall floor, while reordering or deferring cut members loses
the 2 KB guard.

See [Protocol index view](../../packages/protocol/src/recall/conditional-field/index-view.ts).
`RecallNavigationWitness` records original/hint view, native operator,
ordinal, optional access rank and byte location; it is discovery provenance,
not a renamed canonical or associative ranking. `delivery_context` and
`delivery_budget` bind the page fitted to the caller's envelope. Library field
delivery carries the same tagged index and same-order results, with Q/H/C
qualifiers only on delivered source targets. The live public and worker ingress
accept field continuations; retained v6/v7 library and old source-access family
readers exist for archives only. Nested receipt versions must be dispatched
explicitly. Parseability never implies supported execution. Supported public
schema/version changes follow [invariant §25](invariants.md#surface).

## Opt-in open source semantics

`soul.interpretation` retains explicit prepare, source-local H,
source-independent Q, C, selected conditional computation, reason and
invalidation contracts. It neither replaces `soul.recall` nor grants Garden
truth promotion. Raw authorized source access does not require H or C; a
source-only result remains available when optional formation fails. Published
interpretations are source-bound and unreviewed. Producer `interpreted` means
admitted output, not semantic fidelity; abstained, no-executable-proposition,
valid-empty, failed, incomplete, unavailable and unexercised states remain
distinct. Missing Q/C cannot become proof; an explicit selected Q/H/C
hypothesis retains dependencies and unknown world-claim status. Finite closed
computation covers only those admitted premises and their bounded population;
it cannot prove complete natural-language coverage. Invalidation archives the
exact H through Core/EventLog CAS without erasing source or independent H;
changed database revision invalidates frozen handles.

Prepare and native source-recall use bounded current source census and
SourceIndex opportunities, then verify H against actual current source and
scope. The local default `query-conditioned-v1` access order and explicit
`canonical-v1` diagnostic control are not the retired ordinary enumeration
modes. Query embedding is prepared before snapshot, not within a frozen
continuation. Source access orders a bounded observed pool, not all library
members. Query/page leases freeze that pool and carry principal, scope, clock,
budget and database revision; neither a trace page nor a complete observed
prefix closes unvisited sources. Raw sources need no accepted H and may be
selected independently of proof. Proof packages retain each Q/H/C identity,
complete witness and supporting source window; bounded fit may deliver
source-only instead of stripping an oversized proof. A closed conditional
proof does not establish a complete answer or source truth.

The source-feedback Node session is explicit and request-local: a native
accepted source-bound closure may yield a separately metered access hint for
a *fresh* preparation under the captured original query and scope. It is
not an ordinary Recall loop, cross-H join, new public surface, provider fill
or frozen-continuation discovery. A navigation-only session has no joint
chronology/identity result. Source interpretation generation/revision and
query/correspondence requests require their own exact request identities,
authorities and settled attempt records; cache hits and preflight are not new
provider permission. Current exact wire/schema versions live with their
[Protocol source-semantic schemas](../../packages/protocol/src/recall/) and
[SOUL producers](../../packages/soul/src/); no historical response is relabeled
to make it executable. This is an opt-in mechanism, not measured natural-corpus
benefit or an admission gate for ordinary source reads.

## Host occurrence capture

[Protocol host occurrences](../../packages/protocol/src/conversation/host-occurrence.ts)
owns optional `SourceRecordIdentity.host_structure`: a contract, equality digest,
occurrence count and encoded-byte descriptor. Inventory is retained separately,
never ordinary source hydration, attribution or model input. Missing capture is
unknown; a captured empty list is known-empty. Ordered occurrences may have empty
UTF-8 content intervals, open role/channel, independently scoped author/container
references and upstream positions. Local order does not prove upstream order;
complete normalized content is not original-byte fidelity or complete history.

[Core admission](../../packages/core/src/memory/evidence-create/source-admission.ts)
atomically captures source, inventory and nonempty `message` spans from complete
occurrences only. Independently supplied message spans are refused. Trusted host
composition binds issuer/workspace; MCP host-session capture (`host_session` basis)
attests the attached host's container, positions, completeness and fidelity, not
authenticated humans or upstream identities. The benchmark import uses the same
capture owner with a pinned-dataset issuer minted from the verified dataset authority.
The existing renderer returns intervals alongside unchanged bytes. Host-session round
roots are admitted receipt-first with their occurrences atomically; audit failure
retains the committed source, and the next capture of the same messages recovers the
exact retained receipt (original recorded time and issuer) before binding the round.
Erased round text is not re-admitted: the ledger keeps each message's digest, so a
replayed window admits nothing and a changed body conflicts. A message over the
contract's 16 KB limit is refused; a producer that holds longer text sends an honest
`excerpt`.

Exact retention requires the existing source and verified matching inventory;
a descriptor cannot import provenance into an empty store. Lossless transfer uses
sealed SQLite copies. Changes require a new source revision and later recorded
clock; the source-ID formula is unchanged. Source supersession invalidates affected
index state and preparation leases. Governed erasure removes inventory payload while
retaining its unavailable equality descriptor. Startup's newer-schema fence applies.

[Source-owned inventory reads](../../packages/storage/src/repos/field/host-inventory-read.ts)
check workspace, authorization, currentness, retention and binding. They reserve full
metadata/payload/validation/memory allowances before materializing a complete result,
and distinguish unknown, captured-empty, unavailable, invalid and resource-limited.
No prefix is successful inventory. Admission ceilings are 256 occurrences, 65,536
canonical bytes total and 16,384 per occurrence, with bounded decoded strings.
The ordinary 64-KiB source allowance is not raised. `native_structure`, legacy
attribution, root speaker and existing model/factor extraction retain their meanings;
message spans do not enter factor emission or first-span host selection.

## SourceIndex window representations

The [Protocol planner](../../packages/protocol/src/recall/source-index.ts) owns exact
byte coverage and window identity. New embedding bindings default to
`recorded-message-windows.v1` (Protocol 25.0.0, invariant §25 major).
`utf8-byte-windows.v1` remains an explicit control and the reader contract for
existing raw generations. Selection creates a distinct profile/generation and
withdraws prior eligibility until preparation publishes; changing the default
does not relabel or rewrite stored profiles. Rollback explicitly selects and
prepares raw windows anew. The message strategy was introduced as an opt-in in 23.1.0.

The message strategy protects nonempty complete host-occurrence intervals no larger
than `window_bytes`. These are the same admitted facts that produce message spans;
newlines, role markers and excerpts do not create boundaries. Greedy contiguous windows
end at the farthest legal UTF-8 offset within the byte cap. Gaps and oversized messages
may split; bounded complete messages may not. The final two windows move their shared
boundary to minimize byte-length imbalance where legal, retaining the existing boundary
on ties. A short tail remains when whole-message constraints prevent improvement.
There is no overlap, missing content, byte-cap increase or universal whole-message claim.

The source-owned inventory reader supplies separately metered, bounded facts for both
Core preparation and Storage's transactional manifest recomputation. Captured-empty,
empty complete messages, excerpts, unknown capture and non-applicable capsule structure
remain explicit; unknown/non-applicable structure uses the same strategy's UTF-8 fallback.
Unavailable, invalid or budget-incomplete reads refuse preparation, not fallback. No
ordinary source hydration or preparation budget is increased. Structure changes still
require a new source revision; same-generation retries reproduce identical manifests.

Byte windows are not a token estimate. The existing local embedding owner prepares
prefix/special tokens, counts with the loaded tokenizer and refuses `input_token_limit`
before model execution, without truncation. A bounded byte fragment may still exceed
the token cap and leave a partial generation. This opt-in representation is not an
empirically chosen default. Old persisted generations remain readable under their own
profile, but selection/unbind fencing never revives retired eligibility.

An independently selected local Source encoder uses both
`ALAYA_SOURCE_INDEX_LOCAL_MODEL` and the absolute
`ALAYA_SOURCE_INDEX_LOCAL_CACHE_DIR`; omit both to retain the existing shared
embedding provider. The separately selected `Xenova/bge-m3` Source contract uses
q8, CLS pooling, L2 normalization and unprefixed query and source text. Its
1024-dimensional Source vectors never enter Memory or Evidence embedding
backfill. The selected provider has its own readiness and shutdown lifetime; an
unavailable selection does not fall back to the Memory model. Artifacts still
pass the local sealed-tree and self-contained ONNX checks, and the loaded profile
and tokenizer identity bind a new SourceIndex generation. An 8192-token loaded
limit produces an 8184-byte native window; exact token counting may still refuse
an individual window, so that byte limit alone does not establish readiness.

## SourceIndex lexical representations

The explicit `SourceIndexLifecycle.prepareLexical` entry and the idle daemon's
`runSourceIndexLexicalPass(workspaceId, representation, remaining)` prepare native
records and standalone capsules with no embedding binding or dispatch. They share
the bounded native census, source guards and dependency closure with vector
preparation, but have independent selection, generation, pending roots and activation.

Operators can replace an existing lexical selection through the idle runtime:

```bash
alaya source-index-lexical select --workspace <workspace-id> --representation segmented-unicode61.v2 --json
```

The same command accepts `raw-unicode61.v1` and `segmented-unicode61.v1`. It runs
one bounded lexical pass without embedding inference. The JSON receipt retains
selection revision, generation, preparation status and resource accounting.
Only `status: ready` exits zero; partial, unavailable or superseded preparation
returns temporary-failure status75. A persisted partial selection resumes on the
next scheduled pass or repeated command. Stop the existing daemon before using
this standalone CLI so its runtime storage lease is available.

The background producer prepares `SOURCE_INDEX_DEFAULT_LEXICAL_REPRESENTATION`
(`segmented-unicode61.v2`, Protocol 30.0.0, invariant §25 major) for every workspace it
visits that has no explicit selection, whether or not an embedding binding exists; an
explicit selection (for example a raw rollback) is prepared as selected. Lexical takes at
most half of each pass's remaining work and native bytes, and half of discrete roots and
capture pages rounded up. When only one discrete slot remains, ready vector and lexical
work alternate priority on each workspace-ring traversal. The first lexical visit normally precedes
waiting for model binding, and explicit lexical preparation has its own occupancy. A locally timed-out
binding or inference still fences new model work until it settles, while later bounded lexical passes
can proceed. Automatic lexical and vector work debit the same pass allowance; explicit passes retain
their own limits. SQLite transactions and selection/epoch guards still fence every write. Until the
first generation of the selected representation publishes, the reader
serves the raw `source_index_fts` exactly as for an absent selector, so preparation never
causes a lexical outage. The raw reader remains the named consumer of historical
exact-text rows. Explicit `raw-unicode61.v1`, `segmented-unicode61.v1` and
`segmented-unicode61.v2` selections activate only after matching coverage publishes.
Background selection initializes only absent workspaces atomically. If an operator
changes the selection after a scheduled pass captures it, that stale pass is superseded
instead of restoring the old representation.
Changing the selection withdraws prior lexical eligibility immediately; until the new
generation publishes the raw reader serves, never a mixture of the two projections.
A new source epoch's generation reuses the projection and FTS rows of every root whose
`root_key`, content digest and body bytes match the active generation (charged as copy
reads and writes, no analysis units) and analyzes only new or changed roots. A segmented
selection whose segmenter is cold, loading or failed reads the raw index with raw query
tokens; it never mixes the two tokenizations. Model changes/unbind do not affect
lexical selection, and lexical selection does not retire vector generations.

The segmented variant requires the pinned Node Jieba analyzer to be ready; cold,
loading, unavailable and failed analysis cannot publish or serve a ready identity.
Workers warm before snapshot acquisition, not inside reads. Existing unrelated
fail-soft consumers retain their fallback. Source and query expansion share the
Protocol FTS policy; source projection has no query-term cap. Non-CJK source bytes
are preserved in the search projection; raw trigram still indexes exact native text.
The separately stored word projection appends supported CJK pieces without changing
`source_index_text.body`, digest, spans, evidence bytes or embedding inputs. Jieba's
Han/Hiragana/Katakana path is not Hangul segmentation or uniform multilingual quality.
There is no English natural-efficacy claim, stemming, synonyms or stop-word policy.

The v2 representation advances and persists guarded source units of at most 64 UTF-8
bytes, charging each read, scan and expanded UTF-16 code unit to the pass that performs
it. Surface-token units carry across native reads, so source and query expansion use the
same token-relative boundaries. Committed units resume after interruption or restart; invalidation and erasure scrub
them. A new unit starts only with at least 646 work units and 12,288 native bytes
remaining after its source guard and staged-prefix lookup; census, target lookup and
source-specific dependencies require additional allowance. Smaller passes stay partial
until the allowance is increased. Publication waits for the complete root and source-generation guards. The v2
Unicode61 projection contains the unmodified full source followed by each unit's
segmented expansion; raw trigram still uses the original source. Query expansion uses
the same bounded segmenter. Unit boundaries can change segmentation and ranking relative
to the whole-token v1 representation; v2 does not claim v1 parity. SQLite-internal
aggregation and FTS indexing are not measured physical work. An explicitly selected v1
root whose indivisible analysis does not fit the allowance remains partial until a
sufficiently large explicit pass or a selection change; it never borrows vector work.

Protocol 29.0.0 scopes both Unicode61 and raw-trigram BM25 statistics to the selected
active lexical generation (invariant §25 major). Each generation owns two contentless
FTS domains; neither foreign workspaces nor preparing/retired generations contribute
statistics. The fallback raw reader retains its database-wide corpus and reports that
limitation explicitly. Query/source tokenization and lane alternation are unchanged.
Migration 028 atomically rebuilds existing generation domains from retained projections
and exact raw text, then removes the shared projection FTS. No source, vector, selection
or coverage identity is relabeled. Ranking changes once at migration; existing handles
must restart under the new ordinary result version, and frozen benchmark snapshots are
not migrated in place.

The SourceIndex lifecycle reclaims retired generations in bounded transactional pages
under the existing pass work/byte/deadline allowances. Projection deletion scrubs both
FTS lanes, then targets and empty-domain metadata are removed. The active selection and
preparing generations are excluded inside the same SQLite transaction; retries resume
from remaining rows and a failed page rolls back. Retired-only maintenance does not
invalidate the current observable pin. A reader already pinned to an older WAL snapshot
retains its old schema and rows until release; SQLite prevents physical page reclamation
past that snapshot. The writer refuses a caller-owned transaction rather than mutating
its own frozen read. Reclamation receipts report committed pages/rows separately from
native root visits and census calls; SQL-internal deletion and disk cost remain unmeasured.
There is no query-time maintenance or raw-source deletion. Current-binary rollback
selects and prepares raw lexical anew, still with generation-scoped statistics. Restoring
the old ranking/binary requires a retained pre-028 database, never downgrading the live DB.

The idle producer also reclaims retired vector generations, at most one bounded page per visited
workspace and pass, charged to the same work/byte allowance. Each transaction deletes vector rows,
then windows, then targets, and generation metadata last; the current pointer and current-epoch builds
are excluded. An unpointed older-epoch build is first retired because the existing source-epoch guard
already prevents its recovery. Shared root/dependency material and erase barriers remain owned by source invalidation.
An old WAL reader retains its snapshot until release; SQLite's physical pages may remain occupied until
checkpoint. Remaining rows are restartable progress; reclamation keeps pace only when maintenance has
sufficient allowance and execution opportunities relative to newly retired payload.

Migration 025 is additive, with no automatic backfill. Selection/epoch CAS fences
superseded producers; durable pending targets allow bounded restart and payload repair.
Source/dependency mutation and erasure scrub affected historical search projections
through the existing invalidation closure. Activated coverage becomes partial after
payload loss or source changes; changed epochs require a fresh explicitly prepared
generation. Valid-empty is only published after complete enumeration. Preparation
work includes instrumented native reads and one analysis unit per UTF-16 source code
unit analyzed; native bytes exclude search-output allocation. Neither is measured CPU,
SQLite-internal work, process memory or model cost. Failed operations report lower-bound
accounting. Lexical root visits include attempted projection copies and document reads,
including refusals and rolled-back copies. Capture-page visits include empty, refused and
failed census calls. These visits and actual resource costs debit the producer's shared
pass allowance before vector work; pass receipts report the effective restricted limits.
Bounded selection/generation bookkeeping is
administrative work, outside these native-source read counters. Worker warmup uses a separate indexed administrative selector probe, not
source enumeration; native analyzer load cost is not measured by the query ledger.
Lexical preparation checks the producer's absolute wall-clock deadline around bounded
operations and before publication, and yields between census/root batches so queued
cancellation can run. After selection, interruption returns partial with its reason,
incurred resources and the last observed generation snapshot; it does not reread state
after stopping. An already stopped call is rejected before selection.
Persisted work remains resumable. Neither a timer nor these checks preempt an individual
SQLite/Jieba call; a publication already committed by an in-flight activation is not
rolled back or relabeled unpublished. Producer stop retains occupancy until settlement.

Protocol 23.2.0 adds optional lexical generation/representation binding to captured
tokenization and its compact tuple (invariant §25 minor). Existing policy tags and
ordinary ranking/delivery meanings stay unchanged. Continuations retain captured
terms/binding; mutations invalidate their existing snapshot lease rather than
retokenizing under a new selector. Rollback within the current binary explicitly
prepares raw anew; running an older binary requires a retained pre-migration database
copy under the existing newer-schema fence.

## Source disclosure

Every permitted retained-source display qualifies what was actually read:
original body, retained excerpt, gist or interpretation; read evaluation
clock; checked source interval when available; and proof use. The interval end
is exclusive; future start is `before_start`. Unknown or unavailable interval
is not `expired`. A source-only delivery says `not_current_proof`; a delivered
conditional proof says `conditional_support` with unreviewed/world-unknown
qualifiers. Gist and excerpt are reductions, not original-body completeness.
A checked source record's event time is independent of validity and read clock;
missing time is not inferred from storage time. Omission for a tight payload
means undisclosed, not an assertion of source absence.

The live `SourceDisclosure` wire uses the Protocol version-1 compact tuple;
[its codec and historical decoder](../../packages/protocol/src/recall/) are
separate. Current MCP, worker, HTTP and Inspector ingress must not accept
historical named-object disclosures as current bytes. Disclosure qualifies a
read, never changes source authorization, currentness, erasure or proof
admission. Evidence pointers are not witness attribution.

## Governance, accounting and recovery

Ordinary `soul.recall` ignores `recent_turn` and does not enqueue extraction.
`soul.report_context_usage` captures nothing; usage reporting is a
soft read-side signal, not proof of memory truth. Delivery, inspection and
index membership have zero weight as usage evidence. Verified exposure,
principal and semantic identity bind any attribution. Active constraints are
a separate governed response; unavailable constraints reduce content exposure
rather than silently granting it. The
[write and review owners](architecture.md#runtime-write-model) keep proposal,
resolution, EventLog and source-replacement effects outside
Recall ranking.

The Inspector blanket `strictly_governed` promotion action is retired. Historical
proposals remain readable and rejectable, but cannot be accepted or synthesized
into new relations. Historical `strictly_governed` paths still contribute active
constraint disclosure and remain protected from automatic consolidation; these
read and protection consumers preserve existing user decisions. They do not
authorize a new path or replace evidence-grounded, temporally valid assertion
admission.

The request ledger distinguishes charged work, newly allocated logical memory,
retained footprint, native bytes and limits. Work/memory charges do not measure
SQLite physical I/O, CPU, process RSS or peak allocation. Reserve, hold,
refusal, release and reported capacity are not spend; overlapping child and
parent meters cannot be summed into a request total. Native read, solver,
projection, proof and encoding have their own accounted work; interruption
preserves committed progress and charges already spent. Successful delivery
acknowledgment owns the final execution settlement, distinct from a fitted
preparation envelope or optional private diagnostics. A failed/omitted observer
is not zero cost; an unknown in-flight outcome keeps its reservation and
uncertain usage. Retained producer/raw/cache attempts require exact request,
transport, response and settlement proof before reuse. Failed, truncated,
invalid-accounting, pending and unattempted states are not interchangeable;
recovery cannot grant a new call by relabeling history.

Accepted worker RPC rejections emit best-effort private operator diagnostics at
[`RecallReadWorkerLifecycle`](../../apps/core-daemon/src/runtime/recall/recall-read-worker-lifecycle.ts),
using the existing warning sink (daemon stderr). The record correlates worker
thread, request and operation and copies the authoritative worker error under
`failure.error`, including its Core/non-Core classification and available
measurements. This intentionally raw, private evidence can contain sensitive
error text; it is not a public MCP response, prompt input, source record or
execution receipt. Logger secret-field redaction still applies. Diagnostic text
is capped at 8,192 UTF-16 units per field and each details object at 32,768 JSON
UTF-8 bytes; `truncated_fields` and details status distinguish omission from
absence. No failure history is retained in the lifecycle. Sink failure cannot
replace the rejection or quarantine a healthy worker. A missing/disabled sink
or lost log is missing evidence, not zero cost or a recovered historic error.

Currentness, cancellation, retry and deletion remain owned effects. A caller
abort/deadline may end waiting without proving an in-flight native or provider
operation stopped; shared work retains occupancy until actual settlement or
close. Source replacement compares the captured predecessor inside the owning
transaction; a committed source write with incomplete audit/projection is not
rolled back by changing its return label. Erasure and supersession invalidate
current source, dependent interpretation and derived index eligibility; retained
history does not become current proof. SourceIndex unbind retires the generation
and fences old writes. ONNX background preparation has its own resource and
cleanup owner; stop, failure or timeout cannot advertise ready vectors or a
cleanly released resource without observed cleanup. See
[architecture startup](architecture.md#daemon-startup-ordering) and
[invariants](invariants.md#event-and-state).

## Evidence limits and historical records

Finite or planted regressions show their specific mechanism, not provider/cache
availability, source-interpretation fidelity, physical memory bounds, Clock-A,
agent usage or dataset benefit. Measurement needs a matched request, frozen
source snapshot, complete index/results binding and initial exposure; missing
census, cost, observation, closed process or producer receipt remains unknown or
`NOT_REPLAYABLE`, never a zero, miss, valid-empty or complete proof. Archive
readability is not current execution support. Bench reproduction and sampling
policy lives in [bench history](../bench-history/README.md); old ranking prose
lives in the
[historical recall archive](../archive/recall-before-retirement-2026-09-08.md).
Neither is live runtime authority.

14.1.0–20.0.0 listed in its schema, plus exact native 27.0.0/v4, 28.0.0/v5,
29.0.0/v6, 30.0.0/v7, 31.0.0–33.0.0/v8, historical 34.0.0–35.0.0/v9 and current

canonical request policy. Every native pair requires its matching
`ordinary-native-field.vN` public semantics and result/continuation version,

source-record delivery validation, not support for intervening majors, capsule

from the untouched producer version. Authored historical-format tests demonstrate
reader qualification/refusal rules, not genuine historical producer execution.
